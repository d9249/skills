# Structured Visual Decoding Audits

Use for speculative/draft decoding of geometric plans, robot trajectories, boxes and dense motion.

- Separate exact target-distribution preservation from direct geometry acceptance. A schema-valid primitive can be accepted without matching target tokens, but format/range validity is not geometric accuracy, collision checking or a physical safety guarantee.
- Read both paper appendices and the current pinned evaluation runner. A released dense-motion runner can use sequential sampled candidates and ground-truth ADE oracle selection while its AR comparator is greedy. Keep oracle best-of-N accuracy, single-rollout timing and production-selectable predictions separate. Do not retroactively assign the current runner's protocol to paper tables without direct evidence.
- Trace the serialization unit in each artifact. A paper may parallelize points within one future frame while a released implementation emits each point's multi-frame trajectory as a primitive. Preserve paper versus code provenance rather than calling them identical because names match.
- Verify slot roles, block boundaries and target feature passes. One parallel drafter pass still needs target prefill/context update and may require sequential future-frame blocks. Small layer count does not imply negligible trainable parameter count or task-adaptation cost.
- Inspect negative tasks before generalizing trajectory gains. Box precision may require confidence-triggered AR fallback; dense-motion ADE, final error and thresholded accuracy can move in opposite directions. Read actual confidence guard defaults, since current code and paper can use different top-k/spread thresholds.
- Separate open-loop path metrics from closed-loop policy success. Arc-length-resampled waypoints are not fixed-time actuator commands; SR@distance can mean fraction of points, not episode success. Check whether simulation pauses during planning and whether results have repeated train/evaluation seeds.
- Compare matched action architecture/training and matched VLM context separately. Replacing an original text encoder changes more than the decoder; AR-plan, image-context and no-plan controls better isolate what the geometry contributes.
- Bound latency honestly: supplied tool-call/schema prefixes, fresh input and KV state, target-feature extraction, model-stage versus sensor-to-actuator scope, synthetic sums of shared stage means, prior standalone profiles, sample counts, precision and hardware-specific engines all matter. Quality and speed can use different action-sampler step counts.
- Audit training visibility by component. An internal validation split can be held out from action-head fitting but included in upstream VLM fine-tuning; a separate held-out test remains a different claim. Optimizing an action head against validation rewards makes its selection score in-sample without proving test contamination.
- Check release and license boundaries independently. A code drop can precede matched target/drafter checkpoints; existing sibling weights are not the paper model. Apache-licensed code and research/evaluation-only model terms are distinct.
- Validate fetched GitHub identity against current raw files and tree. Rendered/extracted documentation may still show an older sibling project even after the same directory becomes a shared family landing page. Pin exact revisions and follow newly added method-specific docs.
